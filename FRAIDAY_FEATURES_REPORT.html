Executive Summary

Fraiday is an action-oriented AI engineering agent operating directly inside an authorized Windows project workspace. It integrates multi-step reasoning, real-world file CRUD operations, live command execution, physical disk state validation, real-time Server-Sent Events (SSE) streaming, and an interactive Neo-Brutalist dashboard.

1. Multi-Agent Graph Engine (LangGraph Core)

The core execution engine (backend/app/graph) runs an autonomous state-machine workflow:

  • FraidayState: Persistent state model tracking run IDs, objectives, task breakdown, execution history, workspace metadata, tool invocations, artifacts, and validation verdicts.
  • Orchestrator Node: Evaluates the workspace context, file hierarchy, and user intent to generate an action-oriented step-by-step execution plan.
  • Researcher Node: Performs zero-hallucination contextual inspection of existing files, APIs, and directory structures prior to code generation.
  • Dynamic Action Executor: Dynamic multi-turn tool execution loop. Interacts directly with the controlled workspace tools until the objective is reached.
  • Real-World Validator: Validates physical file existence on disk, verifies return codes (code 0), and checks destructive operation authorization.
  • Recovery Node: Autonomous error reflection and targeted patching when execution errors or failed validations occur.

2. Controlled Workspace Engine (WorkspaceManager)

Tool Name Description Security & Policy Controls
list_directory Recursively inspects directory trees and file metadata. Strictly bound within workspace; ignores node_modules, .git.
read_file Reads file contents with line counts and sizes. UTF-8 decoded; rejects paths escaping root workspace.
create_file Creates new files and parent directories on disk. Verified path containment; creates real physical files.
update_file Overwrites or updates existing files with new content. Validates file pre-existence and path containment.
delete_file Safely removes files. Policy enforcement: flags approval_required to prevent accidental data loss.
run_command Executes shell and CLI commands via subprocess. 30-second timeout enforcement, contained working directory.
inspect_runtime Discovers installed developer tooling. Detects Python, Node.js, npm, pnpm, and Git versions.

3. Real-Time Telemetry & SSE Streaming Architecture

Fraiday streams live event updates to the client via GET /api/runs/{id}/events:

  • node_started / node_completed — State machine node transitions.
  • plan_created — Emits structured task lists to the UI checklist.
  • context_loaded — Streams active workspace files, detected runtimes, and session history.
  • tool_call_started / tool_call_completed — Live commands, arguments, durations, and output streams.
  • file_created / file_updated / file_deleted — Real-time disk write notifications.
  • validation_result — Audit and test outcome reports.

4. Neo-Brutalist Web UI Workspace

Built with Next.js 14, Tailwind CSS, and Lucide Icons:

  • Live Execution Graph: Real-time status indicators across Orchestrator, Researcher, Executor, Validator, and Recovery.
  • Dynamic Work Plan: Real-time checklist updating task states (pending, in progress, completed).
  • Agent Activity Stream: Chronological tool call cards with color-coded terminal stdout and stderr.
  • Run Context & Artifacts: Live view of files touched, created, or modified during execution.
  • Model & Mode Switcher: Quick-select modal for Fast, Balanced, or Deep Research modes.

5. Automation & DevOps Scripts

  • start.bat: Single-click launch script. Reads .env, starts FastAPI on port 8000, starts Next.js on port 3000, and opens http://localhost:3000 in your default browser.
  • sync.bat: Single-click git automation. Checks status, stages changes, commits with automated timestamp (or custom message), and pushes to GitHub origin main.
  • Secret Protection: 100% compliant with GitHub Push Protection. All API keys managed via local ignored .env.
